## 常见的失败模式（对照自查）

| 失败模式 | 表现 | 可能归因 |
|---|---|---|
| **假阴性** | 资料里明明有，却答"找不到" | 分块切碎了 / 检索没命中 / 阈值太严 |
| **幻觉** | 资料里没有，却编出了答案 | Prompt 约束不够 / 检索返回无关内容 |
| **答非所问** | 检索到了正确片段，但回答跑偏 | Prompt 组织问题 / LLM 没用好上下文 |
| **部分回答** | "资料没提到 X，但 Y 是这样…" | 边界情况，需定义算不算失败 |
| **跨页信息丢失** | 需要综合多页内容时答不全 | 分块粒度太细，缺少父文档上下文 |
| **代码被切断** | 问到函数实现时答不出 | 分块把代码块从中间切开 |

## 归因定位方法

**关键原则：逐层排查，不要猜。**

```
① 先看检索片段（main.py 会自动打印）
   ├─ 片段里根本没有相关内容  → 问题在【检索层】或更前
   │    ├─ 查 data_processed/*.md     → 预处理丢内容了？
   │    └─ 查 chunks（build_index 会打印块统计）→ 分块切碎了？
   └─ 片段里有相关内容，但回答不对 → 问题在【生成层】
        └─ 检查 Prompt 是否被正确填充
```

**实用命令：**

```bash
# 只看检索，不调 LLM，快速定位
python eval.py --retrieval-only

# 单跑某个用例
python eval.py --case 10

# 看索引块数
python build_index.py --stats

# 看预处理结果（人工检查有没有丢内容）
python preprocess.py --inspect
```
